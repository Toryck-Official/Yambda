# 当前预测器实现与训练阶段说明

记录时间：2026-07-06

## 1. 当前整体阶段

当前项目已经形成了完整链路：

1. 准备日志数据和语义 ID。
2. 训练 future predictor。
3. 训练用户响应模拟器 simulator。
4. 训练策略网络，也就是 HSAC/HPN actor。
5. 在 simulator 中做 rollout 评估，并和 SASRec、HPN、HSRL-offline 做统一口径对比。

现在最新的统一评估口径是：

- 低播放不再算负反馈。
- 只有显式 dislike / unlike 算 fail 和 negative。
- 评估 reward 使用 paper effective reward。
- rollout 最大 20 步，所以 depth 接近 20 是正常现象，不能单独作为优势。

当前 1000 episodes 结果：

| 模型 | reward | depth | reward/step | fail |
|---|---:|---:|---:|---:|
| SASRec-SID | 9.4115 | 19.934 | 0.4721 | 0.0080 |
| HPN-SID | 9.5767 | 19.949 | 0.4801 | 0.0080 |
| HSRL-offline | 9.8025 | 19.958 | 0.4912 | 0.0064 |
| actionQ-HSAC 10k | 9.3909 | 19.943 | 0.4709 | 0.0073 |

结论：当前 actionQ-HSAC 主线虽然能正常训练和评估，但还没有超过 HPN 和 HSRL-offline。它甚至略低于 SASRec。之前 reward 从 7.x 提到 9.x，主要来自评估口径变化，不是模型本身已经明显优于 baseline。

## 2. future predictor 的输入

当前 predictor 是 action-conditioned future predictor。它不是只看用户历史，也不是单独预测下一个 item，而是输入：

1. 当前用户历史：
   - `history_features`
   - `history_feedbacks`
   - `history_event_type_ids`
   - `history_mask`
2. 当前候选动作：
   - `action_features`
   - 也就是候选 item 的 dense feature。

模型先用 Transformer 编码用户历史，得到当前状态向量 `state_emb`。然后把 `state_emb` 和候选 item 的 action embedding 组合起来，进入多个预测头。

这个设计的含义是：同一个用户状态下，不同候选 item 会得到不同的未来反馈预测。

## 3. future predictor 的输出

predictor 主要输出这些字段：

| 输出 | 含义 |
|---|---|
| `response_probs` | 对 listen、like、dislike、unlike、undislike 等反馈的概率预测 |
| `predicted_play_ratio` | 预测播放比例 |
| `predicted_reward` | 预测当前动作带来的即时 reward |
| `regret_probs` | 预测 regret 类型分布 |
| `predicted_future_return` | 预测后续累计收益 |
| `future_regret_prob` | 预测未来出现 regret 的概率 |
| `soft_next_token` | 用于构造软下一状态的中间表示 |
| `candidate_logit` | 候选排序用分数，但当前不是主线依赖项 |

训练 predictor 时，主要用日志里的真实 target item 和后续反馈作为监督信号。也就是说，训练阶段可以看真实未来反馈；评估或策略决策时不能看真实未来，只能用 predictor 自己预测出的结果。

## 4. predictor 信息如何被利用

目前代码里实际试过两类接入方式。

### 4.1 直接 rerank

直接 rerank 的做法是：

1. 策略网络先给出一批候选 item。
2. predictor 对每个候选 item 预测未来收益和 regret 风险。
3. 最终分数为：

```text
policy_score + beta * predictor_side_score
```

其中 `predictor_side_score` 可以是：

```text
predicted_future_return - regret_eta * future_regret_prob
```

这条路线的问题是，它只是把 predictor 当成额外分数加进去。实际效果不好，容易破坏原策略排序。前面评估里，直接 rerank 没有稳定提升，所以不作为当前主实验方向。

### 4.2 modelQ / Bellman 辅助信号

另一条路线是把 predictor 用来估计一个动作的模型价值：

```text
model_q(s, a) = predicted_reward(s, a) + gamma * V(soft_next_state(s, a))
```

其中：

- `predicted_reward` 来自 predictor。
- `soft_next_state` 由 `SoftStateBuilder` 构造。
- `V` 是 value head。

在 HSAC 训练里，当前实现是把这个 `model_q` 作为一个 scalar 辅助项加到 TD target 上：

```text
base_target = simulator_reward + gamma * target_critic(next_state, next_action)
target = base_target + MODEL_Q_WEIGHT * model_q
```

这能跑通，但它还不是最理想的“状态信息融合”。它更像是把 predictor 产出的未来估计当成一个额外标量补偿。前面的实验说明这个信号有时有小幅正向，但不稳定，也没有让主策略超过 HSRL。

因此当前结论是：modelQ 版本保留为阶段性尝试，不宜写成最终主方法。

## 5. Bellman 最优价值方程如何实现

项目里 value 训练的核心思想是近似下面这个式子：

```text
V(s_t) = max_a [ r(s_t, a) + gamma * V(s_{t+1}) ]
```

但我们没有真实在线环境，所以用 predictor 近似动作后的反馈和下一状态：

```text
V(s_t) ≈ max_a [
  predicted_reward(s_t, a)
  + gamma * V_target(soft_next_state(s_t, a))
]
```

实现上分成三步：

1. 对候选动作集合 `C_t` 中的每个候选 item 调用 predictor。
2. 用 predictor 输出的反馈概率、播放比例、reward、regret 概率和 action feature 构造 `soft_next_state`。
3. 用 target value head 计算下一状态价值，然后取候选动作里的最大值作为当前状态的 Bellman target。

训练损失是：

```text
MSE(V(s_t), stop_grad(target))
```

当前代码还额外加了一个 soft state 对齐损失：用日志里真实下一段历史编码出来的状态，约束 `soft_next_state` 不要偏得太离谱。

这个设计方向是合理的，但当前还没有充分转化成最终策略提升。

## 6. 当前效果不佳的主要原因

### 6.1 predictor 的排序能力偏弱

predictor 可以预测一些反馈和 future return，但在候选排序上不够强。之前的候选对比里，predictor 有弱正向信号，但没有明显超过简单相似度或 HPN 本身的排序能力。

这说明 predictor 不是完全没学到东西，但还不足以单独改变策略排序。

### 6.2 reward 信号区分度不够

很多样本的即时 reward 接近或并列，导致“哪个候选明显更好”并不清楚。future return 的区分度比即时 reward 好一些，但噪声仍然大。

这会让 predictor 学到的是平均趋势，而不是足够稳定的动作偏好。

### 6.3 训练和评估目标不完全一致

predictor 用日志里的真实 target item 训练；策略 rollout 时，actor 会产生自己选出来的 item。这个分布和日志行为不完全一致。

所以 predictor 在离线日志上看起来有信号，不代表它在 actor 自己探索出的候选上同样可靠。

### 6.4 modelQ 接入仍然偏临时

当前 modelQ 接法是 scalar 加到 TD target：

```text
target = base_target + weight * model_q
```

这比直接 rerank 更合理，但仍然没有真正把 predictor 的状态信息融入 actor 主干。它不能改变 actor 的状态编码，只是在 critic 目标上加了一个辅助估计。

如果要更接近“状态信息补充”，后续应该考虑把 predictor 产生的 soft next state 或 future state representation 作为 critic/actor 的显式输入，而不是只加一个分数。

### 6.5 当前 actionQ-HSAC 本身还弱于 HSRL

最新对比显示：

```text
actionQ-HSAC reward/step = 0.4709
HSRL-offline reward/step = 0.4912
```

差距不是 RAPI 或 predictor 单独能补上的。当前 HSAC 的策略学习质量还没有达到 HSRL-offline 的离线监督效果。

### 6.6 RAPI 当前没有贡献

最新 actionQ-HSAC 1000 episodes：

```text
base_reward = 9.3909
rapi_reward = 9.3854
delta_reward = -0.0055
```

RAPI 没有带来收益，说明当前后悔记忆机制在这个设置下不是主要提升来源。

## 7. 当前最可靠的结论

1. 数据、语义 ID、simulator、predictor、value、policy、baseline eval 都已经跑通。
2. 当前最强 baseline 是 HSRL-offline。
3. actionQ-HSAC 修正后能正常跑，但没有超过 HSRL，也没有超过 HPN。
4. predictor 目前有弱信号，但作为直接 rerank 或 scalar modelQ 接入时效果不稳定。
5. 后续如果继续做 predictor 主线，重点不应该是简单加分，而应该是更认真地做状态信息融合，或者先提高 predictor 在候选排序上的可靠性。
