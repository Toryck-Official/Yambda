# 初步实验结果

记录时间：2026-07-04

## 1. 已跑实验

### baseline：不接 predictor

训练内容：

- 使用现有 simulator 训练 HPN/HSAC 策略。
- 不使用 predictor。
- 训练规模：100000 episodes。

评估结果，1000 episodes：

| 指标 | base | RAPI |
|---|---:|---:|
| 累计 reward | 9.3979 | 9.3998 |
| 每步 reward | 0.4702 | 0.4703 |
| 平均步数 | 19.988 | 19.988 |
| 显式负反馈率 | 0.0091 | 0.0092 |
| simulator 原始 reward/step | 0.0171 | 0.0172 |
| simulator 原始负反馈率 | 0.3545 | 0.3546 |

结论：

- baseline 可以正常跑通。
- RAPI 在当前设置下提升很小，几乎可以忽略。
- 平均步数接近 20，说明当前退出逻辑比较宽松，不能把“交互很深”当作论文结果亮点。

## 2. predictor 直接加分 rerank

训练内容：

- 不重新训练策略，只在候选 item 排序时加入 predictor 分数。
- predictor 分数来自未来回报和未来遗憾概率。

评估结果，1000 episodes：

| 指标 | predictor rerank base | baseline base |
|---|---:|---:|
| 累计 reward | 9.3080 | 9.3979 |
| 每步 reward | 0.4655 | 0.4702 |
| 显式负反馈率 | 0.0086 | 0.0091 |
| simulator 原始 reward/step | 0.0087 | 0.0171 |
| simulator 原始负反馈率 | 0.3585 | 0.3545 |

结论：

- 直接把 predictor 当分数加到策略分数上，效果不好。
- 虽然显式负反馈略少，但总 reward 和原始 reward 都下降。
- 这条路线只保留为诊断实验，不作为主实验方向。

## 3. model-based predictor：作为训练辅助信号

训练内容：

- actor 仍然按原方式选 item。
- predictor 不直接改排序。
- predictor 预测推荐某个 item 后的反馈和下一状态价值。
- 这些预测只作为 critic 训练的辅助信号。
- 训练规模：10000 episodes。
- 辅助权重：MODEL_Q_WEIGHT=0.05。

训练末尾关键指标：

| 指标 | 数值 |
|---|---:|
| effective reward/step | 0.5424 |
| base reward/step | 0.5425 |
| raw reward/step | 0.0842 |
| 显式负反馈率 | 0.0049 |
| modelQ | 6.4261 |
| modelAux | 0.3213 |

解释：

- 训练没有发散。
- 但 modelAux=0.3213，已经比较大，说明 predictor 辅助信号对 critic 影响明显。

### 200 episodes 初筛

| 指标 | model-based base | baseline base |
|---|---:|---:|
| 累计 reward | 9.4060 | 9.3979 |
| 每步 reward | 0.4703 | 0.4702 |

| 指标 | model-based base | baseline base |
|---|---:|---:|
| 累计 reward | 9.5594 | 9.3979 |
| 每步 reward | 0.4780 | 0.4702 |

结论：

- RAPI 在这个 actor 上反而有轻微负增益：500 episodes 中 RAPI 累计 reward 为 9.5478，低于 base 的 9.5594。
- 当前结果还不是最终结论，因为 model-based 只训练了 10000 episodes，baseline 是 100000 episodes。

## 4. 当前判断

1. 直接加分 rerank 不适合作为主实验。
2. model-based predictor 更有希望，应该继续验证。
3. 交互深度接近 20 是当前评估/退出逻辑导致的，不应该作为正向实验结果写。
4. 下一步应该做更公平的消融：
   - baseline 10000 episodes vs model-based 10000 episodes；
   - model-based 100000 episodes vs baseline 100000 episodes；
   - RAPI 开/关对比。

## 5. 评估口径调整

旧评估口径：

- 只有显式负反馈会触发失败统计和提前退出。
- 连续 5 次负反馈才退出。
- 没有累计 reward 的提前退出阈值。

这个口径太宽松，所以平均步数基本贴近 20。它可以反映策略在 simulator 里拿 reward 的能力，但不适合直接写成“交互深度好”。

新评估口径：

- 低播放也计入失败信号。
- 连续 3 次失败提前退出。
- 保留可选的累计 reward 退出阈值，默认先不打开。

对应配置已经写入 `06_rl/configs/main.env`：

```bash
ROLLOUT_FAILURE_SIGNAL_SCOPE=all_failed
ROLLOUT_NEGATIVE_PATIENCE=3
ROLLOUT_REWARD_DONE_THRESHOLD=
```

后续重新评估 baseline 和 model-based predictor 时，要使用新口径。旧表里的 reward 数值仍可作为阶段记录，但平均步数不再作为结论使用。

### 新口径 200 episodes 复查

评估设置：

- 低播放计入失败。
- 连续 3 次失败提前退出。
- 未启用累计 reward 阈值。

| 指标 | baseline | model-based predictor |
|---|---:|---:|
| 累计 reward | 7.4175 | 7.3435 |
| 每步 reward | 0.4943 | 0.4933 |
| 平均步数 | 15.005 | 14.885 |
| 显式负反馈率 | 0.0073 | 0.0074 |
| failure rate | 0.2832 | 0.2825 |
| raw reward/step | 0.1091 | 0.1091 |
| raw negative rate | 0.2832 | 0.2825 |

结论：

- 新口径下，平均步数已经从接近 20 降到约 15，更符合“低质量交互会提前结束”的直觉。
- model-based predictor 在这次 200 episodes 复查中没有超过 baseline。
- failure rate 略低，但累计 reward 和每步 reward 略低，不能作为有效提升写入主结果。
- 当前 predictor 方向仍应继续，但需要先重训和当前 `predictor_actionfix_1m` 对齐的 future value，再做公平消融。

## 6. actionfix value 对齐后的 10k 训练

- value checkpoint: `artifacts/value_actionfix_hpn_1m/future_value.pt`
- predictor checkpoint: `artifacts/predictor_actionfix_1m/future_predictor.pt`
- policy checkpoint: `06_rl/artifacts/models/modelq_actionfixv_w005_10k_actor`
- 训练规模：10000 episodes
- `MODEL_Q_WEIGHT=0.05`

训练侧对比：

- 下一步必须用新退出口径做 rollout eval。如果 eval 提升，说明强信号有用；如果 eval 下降，应该把 `MODEL_Q_WEIGHT` 降到 0.01。

## 7. 阶段性效果分析

目前不要再把重点放在 RAPI 上。已有结果说明，RAPI 在当前 actor 上经常带来轻微负增益，因此主线应先评估“预测器是否让 actor 本身变好”。

已有对比可以分成三组：

| 实验 | predictor 接入方式 | 结果判断 |
|---|---|---|
| 直接 rerank | predictor 分数直接加到策略分数 | 失败，reward 下降 |
| 旧 modelq | predictor_actionfix + 旧 future_value | 失败，新口径 200 episodes 低于 baseline |
| actionfix value modelq | predictor_actionfix + 对齐后的 future_value | 小幅有效，新口径 200 episodes 高于 baseline |

关键发现：

1. 直接把 predictor 当排序分数用不合适。它会改变动作选择，但没有让 simulator reward 变好。
2. model-based 路线是对的，但 predictor 和 future_value 必须成套。旧 `future_value.pt` 和 `predictor_actionfix_1m` 不匹配时，效果反而差。
3. 对齐后的 `future_value` 让结果从负转正，说明 predictor 信息确实能帮助 HPN，但目前提升很小。
4. `MODEL_Q_WEIGHT=0.05` 的辅助信号已经很强，`modelAux=0.5804` 和单步 `base_reward=0.5425` 同量级，因此继续加大权重不合适。

### 当前能写的结论

可以写：

- 新退出口径解决了平均 step 虚高的问题，平均 step 从接近 20 降到约 15。
- predictor 不能简单作为 rerank 加分项。
- predictor 作为 model-based critic 辅助信号更合理。
- 当 predictor 和 future_value 对齐后，200 episodes 新口径下出现小幅正增益：
  - 累计 reward: `7.4175 -> 7.4800`
  - 每步 reward: `0.4943 -> 0.4947`
  - failure rate: `0.2832 -> 0.2824`

不能写：

- 不能说提升显著。
- 不能说 RAPI 有效。
- 不能把 500 episodes 的 actionfix 结果直接和 200 episodes baseline 做最终对比。
- 不能把平均 step 更高解释为更好，因为 step 同时受退出规则、failure 分布和样本影响。

### 消融是否严谨

目前消融还不够严谨，但已经能定位问题。

已经有价值的消融：

1. 无 predictor baseline。
2. predictor 直接 rerank。
3. modelq + 未对齐 future_value。
4. modelq + 对齐 future_value。
5. RAPI 开关观察。

不严谨的地方：

1. baseline 是 100k 训练，modelq 目前主要是 10k 训练，训练预算不完全一致。
2. 200 episodes 和 500 episodes 不能直接混比。
3. 目前只有一次 seed，没有重复 seed。
4. simulator 的低播放/负反馈分布仍然可能影响结论，failure rate 波动不小。

阶段性判断：

- 作为工程验证，链路已经跑通。
- 作为论文式实验，还差同预算、同口径、同 episode 数的正式表。
- 当前最有希望的主线是 `actionfix predictor + actionfix future_value + model-based critic target`。

### 可改进方向

短期优先级：

1. 保持 HPN 状态维度不变，不改 predictor 网络结构。
2. 不再使用直接 predictor rerank 作为主结果。
3. 固定新退出口径，只比较 base actor，不把 RAPI 混进主结果。
4. 调小或归一化 modelQ 辅助项，避免 `modelAux` 压过真实 reward。

值得改的代码方向：

1. 给 modelQ 做 batch 内标准化或滑动均值标准化，而不是直接加原始 value。
2. 增加 `MODEL_Q_WEIGHT=0.01` 和 `0.03` 的权重消融，验证 0.05 是否过强。
3. 在训练日志里单独记录 `base_target`、`model_aux/base_reward` 比例，方便判断 predictor 是否喧宾夺主。
4. 评估时默认关闭 RAPI 或单独输出 base actor 表，避免 RAPI 负增益干扰 predictor 结论。

主实验表应最终长这样：

| 方法 | 训练预算 | predictor | value 是否对齐 | RAPI | reward/step | failure rate | avg step |
|---|---:|---|---|---|---:|---:|---:|
| Baseline HPN | 10k/100k | 否 | - | 关 | 待填 | 待填 | 待填 |
| Direct rerank | 同预算 | 是 | - | 关 | 已知较差 | 已知较差 | 待填 |
| ModelQ old value | 同预算 | 是 | 否 | 关 | 已知较差 | 待填 | 待填 |
| ModelQ actionfix value | 同预算 | 是 | 是 | 关 | 当前最好 | 当前最好 | 待填 |
| ModelQ actionfix value + RAPI | 同预算 | 是 | 是 | 开 | 当前不推荐 | 当前不推荐 | 待填 |

下一步不是无脑加实验数量，而是把这张表补齐到同预算、同口径。
