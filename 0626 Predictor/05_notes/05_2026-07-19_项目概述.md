# Yambda Future-Aware Predictor 项目概述

## 1. 项目一句话概括

本项目面向音乐序列推荐：先由层级语义策略生成候选歌曲，再预测用户对每个候选歌曲可能产生的播放和显式反馈，并估计这些反馈对后续用户状态的影响，用预测长期价值重排候选，减少只追求当前点击或播放的短视决策。

## 2. 应用场景

目标场景是大规模音乐推荐，具有以下特点：

- 物品数量大，推荐动作空间动态且难以直接枚举。
- 用户反馈不只有播放，还包括 `like`、`dislike`、`unlike`、`undislike`。
- 播放完成度是连续值，并可能超过 100%，反映回拉或重复播放。
- 用户可能先表达喜欢，之后又撤销，当前收益与后续后悔可能冲突。
- 用户偏好同时受当前会话短期意图和跨会话长期偏好影响。
- 只能使用离线日志训练，不能依赖在线试错。

系统动作与用户响应必须分开：

```text
系统动作 a_t：推荐哪个候选物品
用户响应 y_t：播放比例及四类显式反馈
```

## 3. 数据集

项目使用 Yandex Yambda 音乐推荐数据，当前主要读取：

```text
sequential/50m/multi_event.parquet
embeddings.parquet
```

主要字段包括：

```text
用户编号
时间戳
物品编号
事件类型
播放完成度
歌曲长度
是否为自然产生的交互
物品向量
```

原始用户响应事件为：

```text
listen
like
dislike
unlike
undislike
```

数据预处理先按时间间隔切分会话，再聚合同一会话内连续出现的相同物品，形成推荐时间步。单个时间步允许同时包含播放和显式反馈。

数据的关键缺陷是没有明确的 `recommend` 曝光字段。因此当前只能根据可观察交互序列近似还原推荐时间步，不能证明每个物品交互都由平台主动推荐触发。

## 4. 要解决的问题

### 4.1 大规模动态动作空间

直接对全部歌曲计算强化学习动作概率代价过高。项目沿用 HSRL/HPN 思路，将歌曲映射为分层语义编号，由策略网络逐层生成语义路径，再检索候选歌曲。

### 4.2 推荐策略短视

原始候选分数主要表示当前状态下选择某物品的倾向，不能充分回答：

```text
推荐该物品后，用户可能产生什么反馈？
这些反馈会怎样改变后续偏好？
短期收益高的物品是否带来后续负反馈或后悔？
```

本项目增加候选条件预测器，在最终决策前估计候选物品的可能后果。

### 4.3 状态表示不足

单个累计奖励不能代表用户状态；只看最后一个交互也过于局限。本项目使用历史物品、五维反馈、播放完成度、时间间隔、交互来源和会话归属共同建模状态，并区分当前会话短期偏好与历史会话长期偏好。

### 4.4 多反馈与偏好反转

播放和点赞不是互斥行为，`like -> unlike` 也不能压缩成一个普通点击标签。本项目将五类响应建模为非互斥反馈，并继续使用最新 `v2 reward` 表达播放、正负反馈和撤销反馈的综合效用。

## 5. 总体方法

当前系统流程为：

```text
真实历史 H_t
-> StateEncoder 得到状态 z_t
-> HPN 生成候选集合 C_t
-> Predictor(z_t, a) 预测每个候选 a 的用户反馈和即时后果
-> SoftStateBuilder 构造临时预测下一状态
-> ValueHead 估计长期价值
-> 合并 HPN 分数和预测价值进行候选重排
-> 推荐最终物品
-> 下一轮只使用用户真实反馈更新历史
```

核心候选价值目标为：

```text
Q(z_t,a)
= E_{y ~ Predictor(z_t,a)}[
    R(y) + gamma × V(Update(z_t,a,y))
  ]
```

其中：

```text
a：系统推荐的候选物品
y：用户可能产生的结构化响应
R(y)：响应对应的即时奖励
Update：候选与响应条件下的临时状态更新
V：下一状态长期价值
```

在线预测状态只用于当前候选比较，不会写入下一轮真实用户历史。

## 6. 模型组成

### 6.1 语义码本与 HPN

- 使用物品向量构造分层语义编号。
- HPN 根据用户状态逐层预测 SID 路径。
- SID 路径通过索引映射到具体候选歌曲。
- HPN 候选召回决定重排模块能够达到的上限。

### 6.2 共享状态编码器

`StateEncoder` 使用 Transformer 编码固定长度历史，并融合：

```text
完整有序历史状态
当前会话短期状态
历史窗口内先前会话长期状态
```

HPN 与 Predictor 使用同一状态定义，避免候选生成和后果预测对用户状态采用不同口径。

### 6.3 候选条件 Predictor

输入：

```text
当前状态 z_t
候选物品向量 a
```

当前输出：

```text
五维非互斥反馈概率
播放完成度点估计
v2 即时奖励点估计
后悔类型概率
```

反馈分布是主要训练目标，播放、奖励和后悔是辅助目标。

### 6.4 SoftStateBuilder

根据当前状态、候选物品和预测响应构造临时下一状态。离线训练使用真实 `next_history` 经 `StateEncoder` 编码得到的状态监督该模块。

### 6.5 ValueHead

ValueHead 同时学习：

```text
一步时序目标
同一数据切分内的多步 future return
候选集合上的预测后果最大化目标
```

训练使用缓慢更新的目标价值网络稳定自举目标。

### 6.6 候选重排

最终分数综合：

```text
HPN 原始候选分数
预测即时奖励
预测下一状态价值
后悔风险
```

不同来源分数需要归一化并通过验证集调整权重，不能假设默认量纲天然一致。

## 7. 项目定位

当前最准确的定位是：

```text
接在层级语义候选策略之后的、基于预测模型的离线强化学习式前瞻重排
```

它不是纯无模型方法，因为显式学习了候选响应和临时状态转移；也不是完整用户模拟器，因为预测状态不会持续滚动生成虚拟轨迹。

当前工作区中的 HPN 主要通过日志目标 SID 做监督训练，不能直接等同于完整 A2C。若论文要声称完整 actor-critic 强化学习，需要重新接回 actor、critic、行为策略约束和对应训练目标。

当前 Bellman 目标受 Bellman-Jensen 启发，但状态连续、响应多标签且转移使用神经近似，不能声称完整复现原论文的贝叶斯最优价值函数。

## 8. 尝试形成的创新点

以下内容是拟验证的方法贡献，不是已经被实验确认的创新结论。

### 8.1 决策前的候选条件未来预测

不是在推荐后解释结果，而是在最终动作确定前，对 HPN 候选逐一预测用户响应和长期后果，再参与决策。

### 8.2 反馈分布优先于单一奖励预测

保留播放与四类显式反馈的结构，不把用户偏好压缩成一个累计奖励。候选价值再通过响应、奖励和下一状态进行整合。

### 8.3 短期会话与跨会话偏好的统一状态

在同一个状态编码器中同时表示当前会话意图和历史会话偏好，并由候选策略与未来预测器共享。

### 8.4 偏好反转与后悔信息进入前瞻价值

将 `unlike`、`undislike` 和低播放等后悔信号纳入预测与价值估计，使策略不仅优化即时正反馈，也考虑后续负面修正。

### 8.5 响应分支价值

目标设计不是简单把预测分数作为掩码，而是希望对候选可能产生的不同响应分支分别计算：

```text
即时奖励 + 折扣后的下一状态价值
```

再按响应概率求期望。当前代码只完成了该思想的软状态近似，严格逐分支实现仍待补齐。

### 8.6 Bellman-Jensen 风格的候选场景目标

离线价值训练尝试使用多次响应采样和候选最大化目标，将预测分布显式引入候选长期价值学习。该目标是否优于普通期望价值需要通过消融验证。

## 9. 当前完成度

已经实现并通过小规模链路检查：

- `session_run` 推荐时间步构造。
- `v2 reward`、五维反馈标签和切分边界控制。
- 语义码本、SID 映射和候选索引接口。
- 共享 Transformer 状态编码器。
- HPN 候选生成。
- 候选条件 Predictor。
- SoftStateBuilder 与真实下一状态监督。
- ValueHead、目标网络和多场景候选损失。
- Predictor 指标与 HPN 候选重排评估。
- 本机小样本 CPU 训练和单元测试。

尚未完成：

- 全量 Yambda 服务器训练与稳定复现。
- 严格的逐响应分支在线价值计算。
- 播放完成度概率分布，而非单个点估计。
- 显式反馈相关性的联合分布。
- 奖励概率分布。
- 独立的认知不确定性估计。
- 与完整 A2C 主框架的联合训练。
- 有统计意义的消融和推荐收益验证。

## 10. 当前卡脖子的地方

### 10.1 缺少明确曝光日志

数据没有 `recommend` 字段，系统动作只能从交互序列近似还原。延迟发生的 `unlike`、`undislike` 与原推荐物品之间可能存在归因误差。这是数据层最根本的限制。

### 10.2 缺少反事实反馈

日志只包含实际出现物品的真实响应，不包含同一状态下其他候选被推荐后会怎样。Predictor 对未曝光候选的预测属于外推，不能直接验证，也可能被策略利用产生虚高价值。

### 10.3 显式反馈极度稀疏

`like`、`dislike`、`unlike`、`undislike` 远少于播放事件。类别加权只能缓解训练失衡，不能创造信息；权重过高还可能导致显式反馈概率系统性偏大。

### 10.4 长期状态仍不完整

当前长期状态只覆盖最近 `history_len` 个时间步中的先前会话，不是用户完整历史。如果当前会话占满窗口，长期状态会退化为空。

### 10.5 完整响应分支尚未落地

当前在线近似主要是：

```text
预测奖励点估计 + gamma × V(由平均响应构造的 soft state)
```

尚未严格实现：

```text
E_y[R(y) + gamma V(Update(z,a,y))]
```

非线性条件下，先平均响应再更新状态不等于逐分支估值后求平均。

### 10.6 没有可靠认知不确定性

当前 `regret_probs` 表示负面结果风险，不代表模型是否可靠。要处理离线候选外推，需要模型集成、重复前向方差或其他认知不确定性估计。

### 10.7 候选召回限制最终效果

如果 HPN 候选集合不包含真实相关物品，后续 Predictor 和 ValueHead 无法通过重排找回。因此必须先验证 SID 码本质量与 HPN 的候选召回。

### 10.8 训练和推理成本

严格前瞻成本近似随以下乘积增长：

```text
批量大小 × 候选数 K × 响应采样数 M × 前瞻深度
```

完整分支建模会明显增加训练显存和在线延迟，需要向量化、缓存和候选裁剪。

### 10.9 缺少全量实验闭环

当前本机结果只能证明代码链路可运行，不能证明推荐效果。尚需服务器完成全量预处理、训练、校准、候选召回、重排收益和消融实验。

## 11. 最关键的下一步

1. 在服务器完成全量数据审计，统计五类反馈、反馈共现、会话长度和长期状态覆盖率。
2. 完成语义码本、SID 映射、HPN 候选召回的全量验证。
3. 训练并校准 Predictor，分别报告每类反馈的精确率、召回率、F1 和概率校准。
4. 实现逐候选、逐响应分支的价值计算，替代单个平均软状态近似。
5. 增加认知不确定性或数据支持度约束，控制未曝光候选外推。
6. 比较 HPN、HPN 加即时预测、HPN 加软状态价值、HPN 加完整分支价值。
7. 最后决定 Bellman-Jensen 风格目标是否保留为主方法，而不是先预设其一定有效。

## 12. 当前研究问题

项目最终要回答的不是“能否再训练一个响应预测器”，而是：

```text
在缺少在线试错和反事实标签的情况下，
候选条件用户响应预测能否提供可靠的决策前未来信息，
并在不造成未来信息泄漏和候选外推失控的前提下，
改善大规模音乐推荐的长期价值与后悔控制？
```
