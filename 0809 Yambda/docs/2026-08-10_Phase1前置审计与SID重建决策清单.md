# Phase 1 前置审计与 SID 重建决策清单

日期：2026-08-10

状态：已确认。当前禁止训练 SNMPP；先完成 timestamp burst、清洗规则、SID 结构和重建方案。

## 一、已经确认的原则

### 1. SNMPP 主事件

主事件为 `E_n=(u,t_n,k_n,i_n)`：用户、时间、反馈类型和物品。

反馈类型固定为 `like / dislike / unlike / undislike`，只建立四个反馈 embedding。物品信息通过 SID 表示进入事件；禁止建立 `feedback × item` 联合事件词表。

### 2. 主数据不是严格 revision 链

SNMPP 主数据使用完整 explicit-feedback event sequence。严格同用户同物品的 `like→unlike` 与 `dislike→undislike` 只作为 revision 专项分析子集，不筛选主训练数据。

### 3. 不把日志清洗成理想状态机

没有官方证据证明 like/dislike 必然互斥、active 状态不能重复操作，或 revision 必须在观察窗口内找到原操作。因此这些事件全部保留，只增加状态标签。

### 4. 只确定性删除完全重复副本

完全相同的 `(user,item,timestamp,feedback)` 只保留一条。当前 duplicate surplus 为 1,213,728 行；Phase 1 必须记录 before/after、影响用户和物品。

### 5. 同时间戳事件不人工排序

同一 `(uid,timestamp)` 定义为一个 `group_id`。组内所有事件共享 `H_{t^-}`；整个组结束后才一起进入后续历史。禁止把组内前一事件加入 history 后预测下一事件。

### 6. 未匹配 revision 仍是合法观测事件

观察窗口内找不到前序 like/dislike 的 unlike/undislike 保留，并标记 `left_censored_or_unmatched_revision=true`；只在严格 revision delay 分析中排除。

## 二、必须验证的问题

### 1. Timestamp burst

统计 group size 的 P50/P75/P90/P95/P99/P99.9/P99.99/max。对分布导出的候选阈值统计被排除的事件、用户、四类反馈和严格 revision 数量。暂不自动删除。

后续准备：

- `D_all`：保留全部组；
- `D_human_like`：排除经确认的极端 burst；
- `batch_event_flag`：标记极端组；
- sensitivity analysis：比较删除 burst 前后 SNMPP interaction matrix 与预测稳定性。

### 2. 同刻不同反馈

统一称为 `within-group ordering ambiguity`，不称为业务冲突。Phase 1 全部保留、共享 group_id 和 pre-group history，并排除出严格 revision delay 配对。

### 3. SID 结构

重训前确认层数、每层词表、codebook 维度、第五层消歧语义、SID 到 item 的唯一恢复、原 embedding 来源及 interaction leakage。

## 三、Embedding 与 RQKMeans 决策

### 1. 主码本只用真实 embedding 训练

使用 2,367,341 个有真实音频 embedding 的 explicit item 训练 RQKMeans，然后冻结码本。约 450,594 个有 artist/album 依据的缺失物品只在冻结量化器上编码，不参与码本拟合。

### 2. Proxy 必须遮蔽验证

在本来有真实 embedding 的歌曲上做 leave-one-out masking，比较 album centroid、artist centroid、artist+album combination。指标包括 cosine、MSE、SID PrefixAcc@1/2/3/4 和 nearest-neighbor semantic consistency，据此确定优先级和权重。

### 3. 保存 embedding 来源

Canonical item metadata 至少保存：

```text
0 = real
1 = album_proxy
2 = artist_proxy
3 = artist_album_proxy
4 = cold_unknown
```

推荐与预测指标必须可按 real/proxy/cold 分层报告。

### 4. 无任何依据的冷物品

约 57,136 个物品使用统一 global-centroid/unknown semantic representation，不伪造复杂 embedding、不从 explicit item universe 删除。完整 SID 依靠消歧段保持 item 唯一性。

## 五、SNMPP 事件表示

四类反馈使用 `nn.Embedding(4,d_event)`。若四层 SID 对应冻结的 128 维 codebook vector，则 item vector 为四层拼接的 512 维向量；第一版事件表示为反馈 embedding 与 item vector 的拼接。必要时仅训练 `512→64/128` projection，冻结 codebook 不更新。

## 六、下一事件评估

- singleton next group：可以评价 JointExact@1；
- multi-event next group：使用 Group Recall@K、Group Precision@K、true event-pair coverage 和 SID prefix coverage；
- 禁止随机排列同时间戳目标后计算单一 next-event Exact@1。

## 七、严格 revision 子集

单独保留：

- strict like→unlike：6,364,678 对；
- strict dislike→undislike：308,204 对。

要求同用户、同物品、原反馈严格早于 revision、中间状态未被对应 revision 解除、同刻歧义组不参与。该子集用于核对 SNMPP temporal kernel 与真实 delay distribution，不是主训练数据。

## 核心边界

不要把真实日志清洗成想象中的完美用户状态机。主数据尽可能保留真实观测，只删除确定性重复；其他不确定问题通过 group、flag 和专项子集处理。

Feedback 是有限事件类型，item 是事件携带的 SID 语义信息；二者构成完整事件，但不构成百万级联合 event type。
