# SID 重建与 Proxy 验证实施方案

日期：2026-08-10

状态：只读审计和实施设计已完成。当前不训练 RQKMeans、不分配最终 SID、不训练 SNMPP。

## 1. 本阶段假设

新的 explicit-feedback item universe 中，真实音频 embedding 可以定义主音乐语义空间；缺失 embedding 的物品只能在冻结主码本后，通过经过验证的 metadata proxy 或 unknown representation 进入该空间。

## 2. 已确认的旧 SID 契约

| 项目 | 旧实现 |
|---|---:|
| catalog item | 244,553 |
| semantic levels | 4 |
| 每层词表 | 256 |
| codebook shape | 4 × 256 × 128 |
| 每个 codebook vector | 128 维 |
| 第五层 | 按 item ID 确定性分配的 collision suffix |
| 第五层是否有 codebook vector | 否 |
| 四层语义路径是否唯一 | 否，存在 14,640 个碰撞余量物品 |
| 五段完整编码是否唯一 | 是，在旧 244,553 item universe 内唯一 |
| 旧 HPN 实际预测层数 | 4 |
| 旧 HPN 是否预测第五层 | 否 |
| 旧 HPN 碰撞解析 | 同语义前缀内按训练集流行度，再按 dense item ID |

旧 codebook 使用 210,985 个真实、归一化的 128 维音频 embedding 拟合，没有使用 feedback label。旧 proxy item 是用冻结的旧码本量化，没有重新改变码本。

但旧 item universe 来自旧 50M 派生数据，旧 collaborative fallback 使用用户互斥划分，而不是当前完整 5B 协议的 global chronological split。因此旧 SID 可作为结构参考，不能直接作为当前主实验码本。

## 3. 新数据契约

| item 类型 | item 数 | 当前作用 |
|---|---:|---|
| 真实音频 embedding | 2,367,341 | 唯一允许参与 RQKMeans 主码本拟合 |
| 有 artist/album 依据的缺失 item | 450,594 | proxy 通过验证后，用冻结量化器编码 |
| 完全无 embedding 依据 | 57,136 | 使用 unknown/global-centroid 语义表示，仍保留 item 身份 |
| 合计 explicit item universe | 2,875,071 | 当前主实验完整物品集合 |

Embedding source 固定记录为：

```text
0 = real
1 = album_proxy
2 = artist_proxy
3 = artist_album_proxy
4 = cold_unknown
```

## 4. Proxy leave-one-out 验证

### 4.1 样本

从本来具有真实 embedding、且能找到 artist 或 album 同组歌曲的 item 中分层抽样。分层至少考虑：

- artist-only 可重构；
- album-only 可重构；
- artist 和 album 均可重构；
- source group size；
- item explicit-event frequency。

验证某个 item 时，必须把该 item 自己从 artist/album centroid 中剔除。只有组内还存在其他真实 embedding item 时，该 proxy 才算可用，避免把真实答案泄漏回重构向量。

### 4.2 对照方法

```text
album centroid
artist centroid
weighted artist + album centroid
```

组合权重只在 validation partition 上选择。不能先看最终 test 指标再决定优先级。

### 4.3 指标

- cosine similarity：proxy 与真实音频 embedding 的方向一致性；
- MSE：proxy 与真实 embedding 的逐维误差；
- SID PrefixAcc@1/2/3/4：proxy 和真实向量量化后共享前 1–4 层语义 token 的比例；
- nearest-neighbor semantic consistency：proxy 的近邻与真实向量近邻的重叠或排序一致性；
- 按 artist/album group size、item frequency 分层的稳定性。

最终 proxy 规则必须由这些结果决定，不能预设 artist mean 或 album mean 必然最好。

## 5. 新 RQKMeans 拟合流程

```text
2,367,341 real embeddings
    -> normalize using a fixed documented rule
    -> fit four-level RQKMeans
    -> freeze codebooks
    -> quantize real items
    -> construct validated proxy embeddings
    -> quantize proxy items with frozen codebooks
    -> quantize cold_unknown vector with frozen codebooks
    -> assign non-semantic item disambiguation identity
```

四层 codebook 仍优先使用 256 codes × 128 dimensions，保持与现有 HPN 结构兼容。是否调整层数或词表不属于当前默认动作。

2,367,341 × 128 的 float32 主矩阵约为 1.13 GiB。在当前 2 GiB CPU 内存约束下，实施时必须使用 memmap/分块读取，并避免复制完整矩阵；GPU 可用于分块距离计算，但不是前置审计所必需。

## 6. 硬问题：旧的一层消歧码不够

57,136 个 cold_unknown item 若共享同一个 unknown/global-centroid 向量，它们会得到完全相同的四层 semantic path。

旧的单层消歧词表容量为 256，不能区分 57,136 个 item。因为 57,136 小于 256 × 256，所以仅这个冷桶至少需要两个 base-256 消歧层。Artist/album centroid 还可能产生其他大规模同向量桶，因此必须在全部量化完成后审计最大 collision bucket，不能只按 57,136 推断最终容量。

可选方案如下，当前未替用户决定：

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| A. 多层 base-256 消歧 | 在四层语义 SID 后增加足够数量的非语义消歧 token | 保持层级生成形式；每层词表小；完整 SID 可唯一恢复 item | 总 SID 可能由 5 层变为 6 层或更多；HPN 输出头需相应扩展 |
| B. 单层大词表消歧 | 第五层直接允许大于 57,136 的 suffix vocabulary | 完整 SID 短 | 输出头很大且高度不均衡；不再兼容旧 256-way 层级头 |
| C. 语义 SID + 独立 exact-item resolver | 模型只预测四层语义路径，再在桶内做候选解析 | HPN 语义头改动小 | 完整 SID 本身不唯一；解析器需要独立监督和公平协议，不能沿用测试期流行度 |

如果目标坚持“完整 SID 唯一恢复 item”且继续使用层级生成，方案 A 最贴近目标；但这只是技术判断，必须在 proxy 验证和最大 collision bucket 审计后由用户确认。

## 7. 时间泄漏边界

- 音频 embedding、artist mapping、album mapping 属于静态 item metadata，不使用未来 feedback label。
- 当前已确认原则要求为完整 explicit item universe 编码，这会暴露哪些 item 在全期出现，属于 transductive item-universe setting；论文中应明确披露，不能称为完全 time-inductive。
- 若未来使用 collaborative fallback，它只能使用 global train period 内的事件；当前方案不把 collaborative fallback 作为默认 proxy。
- Proxy 组合权重和模型超参数只能用 validation period/partition 选择。
- Exact-item collision resolver 不能使用 validation/test 事件频率。

## 8. 重建后必须通过的检查

1. 四层 codebook shape、dtype、有限值和冻结状态；
2. 所有 2,875,071 个 explicit item 都有 semantic SID 和 embedding_source；
3. 完整 identity path 唯一恢复 item；
4. semantic collision item ratio、bucket count、P50/P90/P99/P99.9/max；
5. 按 real/proxy/cold 分层的 collision 分布；
6. RQ reconstruction MSE 与 residual MSE；
7. 相似 item 的 prefix/近邻一致性；
8. proxy leave-one-out 的 cosine、MSE、PrefixAcc 和近邻一致性；
9. SID mapping 与 item universe 的双向守恒；
10. 训练、验证、测试均不使用未来事件构造 history。

## 9. 旧 HPN 的可复用边界

可以复用：

- hierarchical token generation 的网络结构；
- 四层语义 token 的逐层条件化实现；
- beam search、PrefixAcc、Recall/NDCG 等通用评价代码；
- history encoder 中不依赖旧数据字段的组件。

不能直接复用：

- 旧 checkpoint；
- 旧 244,553-item vocabulary 和 SID mapping；
- 旧 codebook 及其旧 item universe 结果；
- 旧按用户互斥或 listen 派生的数据划分；
- 旧同 timestamp 逐事件 history 更新方式；
- 旧四层 semantic-prefix 碰撞后按训练流行度解析的结果指标。

原因是新协议的 2,875,071-item identity space、global chronological split、shared pre-group history 和最终消歧结构都可能改变输出契约。旧 HPN 因此只能作为 architecture scaffold，必须在新数据和新 SID 上重新训练。若选择多层消歧并要求模型生成 exact item，输出头还需扩展；若选择独立 resolver，则必须单独实现并公平训练该 resolver。

## 10. 当前停止点

当前只完成旧 SID 契约核验和新 SID 重建方案。以下两项未确认前，不训练新码本：

1. proxy leave-one-out 是否证明 metadata proxy 足够可靠；
2. 选择多层消歧、大词表消歧，还是独立 exact-item resolver。
